v0.6.6
------

API changes
###########

* Moved to clearly continuous time for pathway planning (formerly multi-period)
  optimisation. Instead of defining periods, users now can give
  `investment times` at which capacities (may) change. Consequently, many
  parameters that were scalars before can now be iterable. In contrast to the
  former multi-period implementation, it is possible to give a time series of
  fixed capacities without any investment.
* Avoid creation of empty variables (i.e. variable vectors of zero length).
* ExtractionTurbineCHP is deprecated and will be replaced by
  VariableSplitConverter. The new class is more flexible but will cover all
  use cases of the ExtractionTurbineCHP
* Remove `solver-results` attribute from Model class. It will be replaced by
  the new `solver_return` attribute.
* Depreciate `solver_results` attribute from EnergySystem class. It will be
  replaced by the new `solver_return` attribute.
* The variables `positive_gradient` and `negative_gradient` of
  `NonConvexFlowBlock` and `InvestNonConvexFlowBlock` are removed. The
  gradient limits of `NonConvex` flows are now written directly in terms of
  the flow and the status variables.
* Disallow giving too long sequences to the model. Instead of warning and
  trunkating, model building will now fail. (Too long sequencies indicate
  modelling errors.)

New features
############

* VariableSplitConverter: A converter with one input and two competing
  outputs, where the split between the outputs can vary linearly between two
  given, real operating points (e.g. an extraction/backpressure turbine, where
  the split between electricity and heat varies with the amount of heat
  extracted).
* Added a solver attribute to the Results class to get the return values of
  the solver in a structured way
* Added dual-variables and reduced cost to the Results class

Bug fixes
#########

* Gradient limits of `NonConvex` flows had no effect: the limit values were
  not applied. The constraints also multiplied the flow by the binary status,
  so models with these limits could not be written to LP format (e.g. for
  CBC or HiGHS). The constraints are now linear, apply the limits, and allow
  a start-up to and a shut-down from the minimum load.
* With `minimum_uptime`, a start-up in the last `minimum_uptime - 1` time
  steps was impossible, even if the flow stayed on until the end of the
  horizon. Near the end, a start-up now requires the flow to stay on until
  the last time step, as `minimum_downtime` already does for shut-downs.
